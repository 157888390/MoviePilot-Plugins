# 硬链接联动清理（HardLinkCleaner）v1.1.0

单向监控**源目录**，当源目录中的文件/文件夹被删除（或移出）时，自动清理**硬链接目录**中对应的硬链接及其刮削产物，并支持级联清理空目录。

> 与 `strmscraper`（监控 .strm 并刮削）是**两个不同的插件**，职责互补：本插件只负责“删源 → 清链”。

## ⚠️ 重要：v1.1.0 的设计修正（关于误删）

v1.0.0 采用「硬链接目录是源目录的**结构镜像**，可用相对路径互推」这一前提。这在 MoviePilot 下是**错误**的：硬链接库是主程序按刮削规则**重新组织**的（`/电影/动画电影/片名 (年份) [tmdbid]/...`、`/电视剧/...`），与源目录结构完全不同。据此用相对路径反推源文件 → 永远找不到 → 整个库被判成孤儿 → **整库被清空**（实测误删 1 万+ 文件）。

v1.1.0 改用**硬链接的本质——inode** 作为身份标识：

- 源文件 S 与硬链接库文件 L **共享同一个 `st_ino`**。
- S 被删除后，L 仍在，但其 inode 已不在「活源」集合里 → 这才是真正的孤儿。
- 普通拷贝 / 从未作为源的文件，其 inode 不在「已知源」集合中 → **绝不被波及**。

## 核心机制

### 1. inode 身份映射（替代路径镜像）

```
启动时后台扫描：
  source inode 集合  <- 源目录所有文件的 st_ino
  library inode 索引 <- 硬链接目录所有文件的 st_ino -> [路径]
删除事件：
  inode = 源文件记录的 st_ino
  twins = library_inode_index[inode]   # 精准定位孪生硬链接
孤儿扫描：
  orphan = 库中存在 且 曾为已知源 且 当前源已失活 的 inode
```

### 2. 单向监控

- 仅用 watchdog 监控**源目录**（`recursive=True`），**绝不监控硬链接目录**。
- 监听 `on_deleted`：文件/文件夹被删除。
- 监听 `on_moved`：文件被移出源目录（如进回收站、其他盘）→ 视为删除；源内重命名则跳过。
- 创建/修改事件用于记录源文件 inode，供删除时定位孪生硬链接。

### 3. 联动删除

- **文件删除**：删除硬链接文件 + 其同 stem 刮削产物（`.nfo` / `.jpg` / `-thumb.jpg` / `-fanart.jpg` 等）。
  - 不删除剧集级/剧级文件（`tvshow.nfo`、`poster.jpg`、`Season 1/season.nfo` 等，stem 不同）——它们属于整部剧，仅在整目录删除时一并移除。
- **文件夹删除**：`shutil.rmtree` 删除整个硬链接目录及其全部内容。

### 4. 空目录级联清理

删除后从父目录向上级联 `rmdir`，直到硬链接根目录为止（不会删掉根目录本身）。可由「级联清理空目录」开关关闭。

### 5. 去抖与目录吸收

- 删除事件进入队列，延迟 `删除延迟(秒)`（默认 2s）后由后台线程统一执行，避免删除风暴中反复 IO。
- 目录删除事件会**吸收**其下已排队的子文件删除（整目录一次性处理）。

### 6. 孤儿清理扫描

「启动后孤儿扫描一次」或调用 API `GET /hardlink_cleanup`：扫描硬链接目录中**源已失活**的硬链接并清理，再级联空目录。用于修复插件未运行期间产生的孤儿。**受三重护栏保护（见下）。**

## 三重安全护栏（防误删，缺一不可）

1. **源目录存在性**：孤儿扫描前必须确认所有源根目录存在且可读，否则中止。
2. **源非空**：扫描到的活源 inode 数为 0（源被卸载/清空）→ 中止，不信任。
3. **单次删除上限**：拟删除文件数超过「孤儿扫描最大删除数」（默认 500）→ 中止。本次事故级别（1 万+）会被直接拦下。

此外：
- **试运行（dryrun，默认开）**：开启时只记录“将删除”而不实际删除，便于首次运行在日志中确认影响面，再关闭开关正式启用。
- 所有删除前校验目标确实位于硬链接目录内，拒绝越界删除。
- 仅清理「已知源 inode 且已失活」的库文件，普通拷贝/非硬链接文件不受波及。

## 配置项

| 配置 | 说明 | 默认 |
|------|------|------|
| 启用插件 | 开启单向监控 | 关 |
| 级联清理空目录 | 删除后向上级联删空目录 | 开 |
| 启动后孤儿扫描一次 | 启动 5 秒后跑一次孤儿清理（受护栏保护） | 关 |
| 试运行(只记录不删除) | **默认开**，确认后再关 | **开** |
| 源目录 | 仅监控这些目录，每行一个（如 `/media/downloads/tv`） | 空 |
| 硬链接目录 | 不监控，仅清理（如 `/media/library`） | 空 |
| 监控模式 | 兼容模式（轮询，网络盘）/ 性能模式（inotify） | 兼容 |
| 删除延迟(秒) | 删除去抖窗口 | 2 |
| 孤儿扫描最大删除数 | 单次删除上限（爆破半径护栏） | 500 |

## 依赖

无额外依赖。`watchdog` 为主程序自带。

## 推荐上线流程

1. 配置源目录与硬链接目录，**保持「试运行」开启**，启用插件。
2. 触发一次孤儿扫描（API 或启动扫描），在日志中检查 `[试运行] 将删除` 列表是否符合预期。
3. 确认无误后，关闭「试运行」，插件即正式生效。

## 删除链路示意（inode 基）

```
源 /media/downloads/tv/Show S01E01.mkv 被删除
  → watchdog on_deleted，查源 inode 记录
  → 定位硬链接孪生：/media/library/电视剧/Show/Season 1/Show S01E01.mkv（同 inode）
  → 删除：该 .mkv + 同 stem 的 .nfo / .jpg / -thumb.jpg ...
  → 若 Season 1 变空 → 删 Season 1 → 若 Show 变空 → 删 Show（级联）
```
